Backend Documentation (Laravel)
================================

Overview
- Framework: Laravel 12 (PHP >= 8.2)
- Auth: Laravel Sanctum token-based auth (see api routes). Laravel Passport is installed but not currently wired in routes.
- API routes live in backend/routes/api.php
- Web route (/) returns the default Laravel welcome view.

Project Layout (backend/)
- app/Http/Controllers
  - Api/AuthController.php: login/logout
  - Api/EventController.php: CRUD for user events
  - ChatController.php: AI chat proxy via Hugging Face
- app/Models
  - User.php: users with hasMany events
  - Event.php: event model
- database/migrations
  - create_users_table.php
  - create_events_table.php
  - create_personal_access_tokens_table.php (Sanctum)
- routes/api.php: API endpoints
- routes/web.php: web root

Environment
- See backend/.env.example for defaults.
- Required for chat endpoint:
  - HF_TOKEN: Hugging Face API token (used by ChatController)

Setup (local)
1) Install dependencies:
   - composer install
   - npm install
2) Create env and app key:
   - cp .env.example .env
   - php artisan key:generate
3) Migrate database:
   - php artisan migrate

Notes
- Default DB is SQLite per .env.example (DB_CONNECTION=sqlite). You can switch to MySQL by setting DB_* values.
- Queue connection is set to database (QUEUE_CONNECTION=database). If you run queues locally, use: php artisan queue:listen

Running
- Development (from backend/):
  - php artisan serve
- There is a composer script "dev" that runs server, queue listener, logs, and Vite concurrently:
  - composer run dev

API Authentication
- Auth uses Laravel Sanctum.
- The login endpoint returns a personal access token. Send it on subsequent requests:
  - Authorization: Bearer <token>

API Endpoints
Base path: /api

1) POST /api/login
- Body: { "email": string, "password": string }
- Response: { "token": string }

2) POST /api/logout (auth required)
- Response: { "message": "Logged out" }

3) POST /api/chat
- Body: { "message": string }
- Response: { "type": "ai"|"handoff"|"error", "reply": string }
- Behavior:
  - If message contains "human" (case-insensitive), returns type=handoff.
  - Otherwise calls Hugging Face Router with model "Qwen/Qwen3-Coder-Next:novita".
  - Optional system prompt is read from storage/Agent.txt if it exists.

4) GET /api/events (auth required)
- Response: list of events for the authenticated user

5) POST /api/events (auth required)
- Body: { "name": string, "date": YYYY-MM-DD, "time": HH:MM[:SS], "description"?: string }
- Response: created event

6) PUT /api/events/{id} (auth required)
- Body: { "description": string }
- Response: updated event

7) DELETE /api/events/{id} (auth required)
- Response: { "message": "Event deleted" }

Data Model
Users
- id, name, email, password, timestamps
- Relationship: User hasMany Events

Events
- id, user_id, name, date, time, timestamps
- Relationship: Event belongsTo User

Important Implementation Notes
- EventController validates a "description" field on create/update, but the events table and Event model do not include a description column/attribute. If you need descriptions saved, you must add a migration column and add "description" to Event::$fillable.
- routes/api.php defines password reset routes (POST /password/forgot and POST /password/reset), but the corresponding controller methods are not present in Api/AuthController.php. These routes will currently fail unless implemented.

Testing
- PHPUnit is configured. You can run: php artisan test
